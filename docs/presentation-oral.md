# 高校综测系统 — 口头汇报稿（约3分钟）

---

各位好，下面我来汇报高校综测系统的技术方案和设计思路。

**项目定位**上，这是一个覆盖高校综合测评全流程的管理平台，从学生上传材料、AI 智能解析、教师审核评分，到公示排名、申诉处理、成绩导出，形成完整闭环。

**技术选型**上，后端采用 Python Flask 加 PostgreSQL，前端采用 Vue 3 加 TypeScript。选择这套组合的考虑是：Flask 轻量灵活，适合快速迭代；Vue 3 的 Composition API 加上 TypeScript 提供良好的开发体验和类型安全。部署方面使用 Nginx 反向代理加 Gunicorn 多进程，由 systemd 管理进程生命周期，整体是一套成熟稳定的 Linux 服务架构。

**设计思路上有四个核心点：**

第一，**Agent 协作模式**。我们参考了总控调度官的架构思想，设计了一个 MasterAgent 协调十四个 Worker Agent。每个 Worker Agent 负责一个业务领域——比如 AuditAgent 管材料、CounselorAgent 管审核、PublicityAgent 管公示——它们各自维护自己的业务逻辑，互不耦合。MasterAgent 用线程池并行聚合数据，比如登录后同时拉取待审数量、排名、风险报告，前端只需要一次请求就能拿到完整的仪表盘数据。这种设计的好处是：职责清晰、易于扩展、天然支持并行。

第二，**状态机驱动**。综测材料的流转本质上是一个严格的状态机——从草稿到提交、审核、通过、公示、归档，共八个状态。我们建了一个独立的状态机模块，明确规定了每种状态下的合法操作和非法操作。比如材料在公示中、公示结束、申诉处理中这三个状态下是锁定的，禁止修改。任何非法状态跳转都会被拦截并返回明确的错误信息。这保证了数据一致性和业务流程的严谨性。

第三，**AI 能力嵌入**。我们接入了两个 AI 服务：DeepSeek V4 Pro 负责自然语言理解和 PDF 文本解析，SiliconFlow 的 Qwen3-VL 多模态模型负责图片 OCR。学生上传证书照片或 PDF 后，系统自动提取标题、证书编号、颁发单位，再经过内置的评分规则引擎——这是一个基于关键词匹配的打分系统，区分国家级、省级、校级等不同层级，处理队长与成员的权重差异——最终给出评分建议。学生确认后即可提交，大幅降低了手动填写的成本。

第四，**评分规则引擎**。这是一个独立模块，将综测评分标准——德育、智育、体育、美育、劳育、能力六大类——转化为可配置的规则集合。每条规则定义了关键词匹配、等级系数、得分上限、成员折算等参数。引擎输入材料文本，输出结构化评分结果。新规则只需添加配置，无需修改核心代码。

最后补充一点**安全性**方面的考虑。我们实现了双重认证机制：内部用户使用 JWT 令牌，12 小时过期；外部系统通过 API Key 接入，密钥格式为前缀加随机串，数据库中只存哈希。上传文件有类型和大小限制，Nginx 和 Flask 两层都设了 10MB 上限。风险检测模块在上传时自动拦截重复证书、过期证书和未来日期的异常数据。

以上是技术方案和设计思路的汇报，请各位指正。
